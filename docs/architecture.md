# LeafSweeper — Architecture

## Overview

Godot 4.7 C# (.NET 8), **code-first scene construction**: `scenes/Main.tscn`
is a single `Node2D` with `scripts/Main.cs` attached; every other node is
built and wired in C#. No physics engine — debris motion is a lightweight
hand-rolled model (velocity, spin, friction) that is predictable and cheap on
mobile.

## Scene tree (built at runtime by `Main.BuildTree`)

```
Main (Node2D, scripts/Main.cs)
├── Ground (Node2D)
│   └── Sprite2D              ground.svg (ground_winter.svg in winter),
│                              scaled to cover viewport
├── DebrisBottom (Node2D)     70% of debris — ZIndex 1, always over the bug
├── Bug (Node2D)              hidden until StartLevel — ZIndex 0 (below debris)
├── DebrisTop (Node2D)         30% of debris — ZIndex 2, always over the bug
├── StormDrift (Node2D)        storm rafts mid-crossing — ZIndex 3 (spawned on
│                              a 10–20s storm timer, frees itself offscreen)
├── SeasonGrade (CanvasLayer 1)  per-season full-floor color grade
├── StormOverlay (CanvasLayer 2)  storm veil/rain/mist over the world
├── Menu (CanvasLayer 3)        title screen
├── Hud (CanvasLayer 4)         wood dock + top labels + win overlay
├── StormWarn (CanvasLayer 5)    "Storm Round" electrical warning sign
├── PrismaticSign (CanvasLayer 6) "Prismatic" banner riding out a find
├── SeasonBanner (CanvasLayer 7)  season-intro / year-loop bonus card
├── BugBook (CanvasLayer 90)  full-screen collection book; above the HUD
│                             so the dim blocks the dock while it's open
```

CanvasLayer order is an explicit ladder (season grade 1 → storm 2 → menu 3
→ hud 4 → warn 5 → prismatic 6 → season banner 7 → book 90): same-layer
canvases draw in a non-deterministic order, so every layer gets its own
index. The seasonal grade sits directly above the world; the storm veil
and rain ride above it, and every UI above that.

## State machine

`Main` holds `GameState { Menu, Playing, Won }`:

- **Menu** — `MainMenu` visible, level cleared.
- **Playing** — input routed to the sweeper and the bug tap check.
- **Won** — celebration + `Hud.ShowWin(comment, statsLine, bug, grandiose)`;
  a prismatic find passes `grandiose: true` for the radiant gold card.
  Next → `StartLevel(save.CurrentLevel)` (RecordClear already advanced it),
  Menu → title.

## Modules

| Script | Responsibility |
|--------|----------------|
| `scripts/Main.cs` | Controller: builds tree, state machine, level setup/teardown, input routing (a tap only wins when the bug is uncovered — `BugIsCovered` runs the pixel-accurate `Debris.Covers` test against the bug's occlusion area, far tighter than its tap area; a covered tap starts sweeping instead; a tap inside an active `IceBlock` that isn't on debris cracks it instead — gated on the collected hammer power-up (`_hammerArmed`; the third crack wins the round), each crack also firing the hammer's shockwave — a `Sweeper.Burst` at the ice center with twice the burst radius (`CrackDispersalRadius`) whose cleared ground joins no backfill pool (`recordSpots: false`), so the storm can't re-litter the dig — with a locked pulse when it isn't armed; uncovered gust coins are collected the same way via `DebrisOverlaps`/`SelectableCoinAt` against the coin's occlusion radius, and the buried blizzard hammer via `SelectableHammerAt` (collecting it reparents the hammer onto the HUD layer for a clockwise spiral flight to the top-middle power-up slot where it floats; `OnSettleFinished` spawns one per blizzard round, `ClearLevel` tears it down)), win flow, debris spawn layout (inside the playable rect above the HUD dock) with the round-start **settle-in** (pieces drop in tumbling, staggered along the diagonal — touches and gusts stay locked until the floor is dressed, then `OnSettleFinished` places the bug and the gust coins (`RoundConfig.GustCoinsForLevel`: one on normal rounds, three on storm rounds) at new random spots underneath and starts the round clock; the dock restart button funnels through the same `StartLevel` settle, so restarting reshuffles the litter and the hiding spots too), gust coin collection (`CollectCoin` lifts the coin onto the HUD layer so it flies above the dock; the +1 `gustPower` is banked when the coin arrives, then `Hud.PulseGustPower` fires), wind gust (clears ~25% of remaining debris with streak effects; spends one gust power and counts the use per round), win-flow **end-of-round wind** (`StartEndRoundWind` lifts every leftover piece into a clockwise gyre around the floor's center via `Debris.StartEndRoundWind` — the litter keeps circling while the win card is up; `WindCenter` is the playable floor's middle during a round and the whole viewport's middle on the menu, refreshed on viewport resize), **menu gyre** (`SpawnMenuDebris` scatters a decorative litter over the whole screen and lifts it into the same gyre idled down to `MenuWindSpeedScale` so the home card floats over a slowly spinning floor), restart handling, petal sparkle, and the **prismatic roll**: `OnSettleFinished` rolls a 1% chance (`PrismaticChance`; `LEAF_PRISMATIC=1` forces it) of a prismatic bug, places it uncamouflaged, and a find spawns the `SunFlare` at the winning tap, shows the grandiose win card (`WinLevel` → `RecordClear(..., prismatic)` → `OnBugCelebrationFinished` → `ShowWin(..., grandiose)`) and rides the **Prismatic banner** out after the round (`PrismaticSign.ShowSign`; the next `StartLevel` holds it over the round's opening, then dissolves it — `LingerThenFade` — and menu returns hide it). Season wiring: `StartLevel` resolves the round's season (`ResolveSeason`; `LEAF_SEASON=spring|summer|fall|winter` forces the display/vibe season only — level-derived mechanics always key off the true level season), tags the HUD level label ("Level 120 · Summer") and announces changes through the `SeasonBanner` — once per session per season (`_announcedSeason`), with a loop restart showing the bonus card instead (`_announcedLoop`; both persist across rounds, menu returns hide the banner). The same resolved season drives the vibe: `SeasonGrade.ShowSeason` fades the floor grade in (out on the menu), the litter mix re-weights (`EffectiveFrequency`: summer leans green, fall goes red/gold, winter mixes snow flecks in and thins leaves) and winter swaps the ground sprite for `ground_winter.svg`. Season **events** churn summer/fall storm rounds: `TickSeasonEvent` counts down `TornadoInterval`/`StreamInterval` (suppressed in autoplay, hand-triggered for probes), `TriggerSeasonEvent` starts the funnel's telegraphed crossing (summer) or the full-floor shimmer wash (`WaterStream`, fall), and at touchdown `ShuffleRound(fraction, slide, direction)` relocates a fraction of the at-rest debris **plus the bug and uncollected coins** — half for the tornado, everything for the streams, whose targets are biased downstream along `WaterStream.Direction` and resampled until the move is visibly real (`ShuffleMinMove`, so no piece "relocates" into its own footprint); debris lifts and tumbles (`Debris.RelocateTo`, low hop on the slide), bug/coins glide (`GlideNode`/`TickGlides`, arc for the tornado, flat slide for the streams), touches stay locked while anything is mid-flight (`UpdateShuffleLock`), and `CancelShuffle` kills it all on win/menu/restart. Also hosts the `LEAF_AUTOPLAY=1` headless self-test, which verifies the coverage rule against alpha ground truth sampled straight from the blocker texture, asserts the menu litter is riding the gyre, exercises the restart handler (settle gate must re-engage) and asserts the win wind picks every piece into a clockwise-moving gyre. While a round is live and settled, `_Process` counts down 2–4s and `TriggerAmbientRustle` lets a stray draft shiver a random at-rest piece plus the closest 4–7 of its neighbors along a shared direction (see `Debris.Rustle`) — cosmetic only. On storm rounds the same gate runs the storm pacing: `TickStormDrops` re-litters each recorded cleared spot on its own 4–6s timer (spots via `RecordClearedSpot`, pool capped at 400) and `TickClusterDrops` dumps a cluster of 6–12 brand-new pieces onto random floor spots every 4–6s — **20–34 on blizzard rounds** (`WinterFloodMin`/`WinterFloodMax`: the winter flood is the blizzard's signature beat, a single exhale that visibly buries the floor; the same 3× cap tapers it) — (shared `SpawnStormDebris(pos, snowPile)` spawn path — on blizzard rounds the flood drops white snow piles while spot restoration backfills ordinary winter litter; both paths re-roll/skip spots inside the ice rescue zone `BlizzardRescueClearance`, so the blizzard never re-buries the ice the player is excavating), stopping for the round once the live debris count reaches 3× the round's starting litter (`StormFloodCapMultiplier`) while spot restoration keeps going. Two more storm-only cosmetic timers run on the same gate, each on its own 10–20s cadence: `TickSpiralRustle` → `TriggerSpiralRustle` shivers the litter inside a swirl of radius = 1/10 of the playable floor's smaller dimension (diameter ≤ 1/5 screen) along the clockwise tangent, each piece's shiver delayed by its clockwise angle from the 12-o'clock start (`Debris.Rustle` lead-in) so the gust reads as a spinning wave; and `TickStormDrift` → `SpawnStormDrift` sends a `StormDrift` raft of decorative debris spiraling across the screen offscreen-left → offscreen-right (ZIndex 3, touches no gameplay debris, `CancelStormDrift` on win/restart/menu). The autoplay suppresses the three cosmetic timers (`_suppressStormEvents`) and triggers each by hand for deterministic `AUTOPLAY spiral` / `AUTOPLAY drift` probes. |
| `scripts/Sweeper.cs` | Input-to-interaction: converts touch stream into flings. Uses a **segment-vs-circle sweep test** (sweep radius 55 + 30 margin) between successive touch positions so fast sweeps can't tunnel over debris, and enforces a **per-sweep cap** of cleared debris (`MaxDebrisPerSweep`, instance value — 12 base, +2 per completed year, applied at round start via `SetSweepPower`). Emits `onSweepCompleted` only for finished touches that cleared at least one piece of debris, so bare taps never count as sweeps; a second simultaneous touch is ignored while a gesture is in flight. Each flung piece is also reported through the `onDebrisSwept` constructor callback (before it flies) so storm rounds can record the vacated spot. The double-tap **burst** (`Burst`) is the drag-free cousin: pieces nearest the tap within `BurstRadius` (130) fling radially, sharing the cap, the callback and the `onSweepCompleted` accounting; optional `radius`/`recordSpots` parameters let the hammer crack reuse it as a shockwave at twice the radius with backfill recording switched off. |
| `scripts/Debris.cs` | One debris item: weight class (Light/Medium/Heavy → fling factor 0.65/0.5/0.35, friction 3.4/2.3/1.5, fade-delay scale 1.0/1.35/1.7 — heavier pieces launch slower but glide farther and linger before fading), `Fling(velocity, rng)`, `Covers(worldPoint, radius)` — the pixel-accurate overlap test behind the covered rule: early circular rejection via `ExtentRadius` (bounding circle), then a scan of a per-texture cached `AlphaMask` (one byte per 4px cell, built once from the texture's alpha channel), so debris floating in a texture's transparent margins no longer hides the bug or coins — per-frame slide+spin+fade, `QueueFree` when faded. Round-start `SettleIn(rng, delay)` drops the piece onto its assigned spot from above with a tumble and quart-out landing (fade-in over the first third; `IsSettling` gates play until every piece lands). After a win, `StartEndRoundWind(center, rng)` puts survivors on a clockwise orbiting gyre — per-piece speed jitter shears the ring, the lane radius breathes, the whole gyre bobs, pieces tumble and never fade while `IsRidingWind`. `Rustle(dir, falloff, rng, delay)` lets an ambient draft shiver the piece in place for ~0.5s (an optional `delay` holds the shiver back — the storm's spiral gust staggers pieces by their clockwise angle so the swirl reads as a rotating wave) — the wobble lives on the child sprite only (weight-scaled amplitude: leaves flick, rocks barely budge), so the node transform behind `Covers`/sweep/gyre math never moves. Unclamped — swept pieces may drift over the dock while fading; only *spawning* is excluded from it. |
| `scripts/Bug.cs` | Bug display: `Setup(variant, scale, camouflage, prismatic)` applies the variant texture and tints toward leaf color, `TapRadius` (type radius × scale) with `ContainsPoint(world)` plus the much tighter `OcclusionRadius` (type occlusion radius × scale) that the debris-clearing rule uses, `Celebrate(centerTarget)` plays the golden discovery moment — the bug rises to `ZIndex` 100 above all debris, a shining outline (via `assets/shaders/gold_outline.gdshader`) fades in while it swells to 1.45×, then it flies to the screen center — and emits `CelebrationFinished` when the win overlay may seat it. When `prismatic` is set the sprite's material swaps to `assets/shaders/prismatic.gdshader` (hue-crawling rainbow + sparkle glints, gold outline for the celebrate tween) and camouflage is bypassed; the bug stays at ZIndex 0 below every debris layer so the effect can never leak through the leaves. |
| `scripts/GustCoin.cs` | One collectible gold gust coin (reuses `assets/icons/coin.svg` + the gold outline shader, with the **wind icon** on its face like the dock's gust button): sits at `ZIndex` 0 below all debris, `TapRadius`/`ContainsPoint` plus a tight `OcclusionRadius` (0.3 × size, hugging the drawn disk) like the bug; `Collect(dockTarget)` marks it collected, plays the golden swell, then **winds up a rising counter-clockwise loop** above its pick-up spot (`LoopTurns`/`LoopSeconds`, radius from the coin→button distance clamped to `LoopRadiusMin..Max`, tightened by `LoopShrink`) before **dashing down onto the gust button** — riding above the dock (Main reparents it onto the HUD layer); every loop point is clamped into the viewport inset by `PathScreenMargin`, so the loop hugs the screen edges instead of arcing out of view — emits `CollectionFlightFinished` the instant it lands, and melts into the button before freeing itself. |
| `scripts/BugTypes.cs` | Static catalog of 39 species (texture path, display name, relative size, tap radius, occlusion radius — 45% of the tap radius clamped to 18–36px) each with **4 color variants** (`BugVariant`: id, display name like "Yellow Ladybug", texture path, back-reference to its species) — 156 book entries. The `Sp` helper builds a species: the base texture becomes the first variant under the bare species id (older saves keyed by species id keep counting), then `id_suffix` variants follow. `RandomVariant()` drives spawns, `VariantById()` resolves save keys. |
| `scripts/Hammer.cs` | The blizzard rescue key (reuses the gold outline shader with the hand-authored `assets/icons/hammer.svg`): one mallet per blizzard round, spawned by `Main.SpawnHammer` in `OnSettleFinished` at a `CoinSpot` and hidden below all debris (`ZIndex` 0) with the coin's dual-radius contract (`TapRadius`/`ContainsPoint` for taps, a tight `OcclusionRadius` — 0.32 × size — for the cover rule). `Collect(floatTarget)` marks it collected, plays the golden swell, then **winds up a rising CLOCKWISE loop** (the gust coin's spiral mirrored — angle increases instead of decreasing) before dashing to the top-middle power-up slot (`Main.HammerFloatHeight` = 150px); every loop point is clamped into the viewport inset by `PathScreenMargin` like the coin's. It emits `FloatStarted` on arrival — Main banks `_hammerArmed` there — swells with a Back ease into **float size ≈ 2× the found size** (`FloatScale` 1.6: the parked power-up is a banner, not floor clutter), and then **floats in place** (`_Process` bob + sway around a screen-relative anchor, re-parked via `SnapFloat` on viewport resize) instead of melting away: it's a held power-up, not an absorbed one. |
| `scripts/RoundConfig.cs` | Difficulty curves saturating at level 200: `Coverage` (debris density as floor-area fraction), `BugScale`, `Camouflage`, `IsStormLevel` (every 10th level from level 10 on) and `GustCoinsForLevel` — `NormalGustCoins` = 1 gust coin on normal rounds, `StormGustCoins` = 3 on storm rounds (the flood re-buries ground, so storms pay in gusts), `+LoopGustCoinBonus` (1) per completed year. **Seasons**: the difficulty progression — nested `Season` enum, `SeasonForLevel` (`level / 100 % 4`: 1–99 Spring, 100–199 Summer, 200–299 Fall, 300–399 Winter, 400+ the year loops), `LoopIndex` (`level / 400`, 0-based year), `SeasonLength`/`LoopLength` consts, and the stacking loop bonuses (`SweepPowerForLevel` = 12 + 2/year — config-only until the sweeper wires it — and `GustCoinsForLevel`'s `+1/year`). Pure functions — easy to tune. |
| `scripts/LevelStats.cs` | Round statistics: tick, sweep count, gust power uses, formatted time, and `Comment(save, bug)` template picker (praise / cozy / best-yet / time / color lines). |
| `scripts/Hud.cs` | In-game UI: a **wood dock** along the bottom (fixed `DockHeight`, bark-textured `assets/textures/wood.svg`, three equal expand-fill columns so the middle stays centered: **book coin** left, Gust coin centered, Restart coin right — dark-gold coin buttons via `assets/icons/coin.svg`; the Gust coin wears a small **bronze counter badge** top-right showing the gust power balance, and the button is disabled at ×0) — hidden only on the menu — plus the **sweeps counter label top-right** (plain text in the level-label style, reading "{x} Sweeps") and the **level label top-left**, the win overlay (title, **bug seat slot** the celebrated bug is reparented into, comment, stats, Next/Menu — `ShowWin(..., grandiose)` swaps the panel to a lighter near-white style with a gold rim and adds the `PrismaticGlow` rays/sparkles + a looping prismatic title color cycle behind the title) and a Restart confirmation dialog. `PulseGustPower` greets each landed coin with a badge pop + gold flash, an expanding ring-and-spark burst and a button glitter. Static `MakeLabel`/`MakeButton` helpers shared with the menu. |
| `scripts/MainMenu.cs` | Title screen: Play (resume), New game (shown only after ≥1 clear), a season progress line ("Season: Summer · 34/100" — the save's next round's season and position in it; the first Spring is the only 99-level season), lifetime progress (levels, time, gusts) + favorite critter, and a version line under the buttons in one of three states: gold, tappable "🌐 Update Available (vX.Y.Z)" (a `LinkButton` whose `Uri` opens the releases page) when a newer GitHub release exists; a muted, inert "vX.Y.Z" showing the installed version when up to date; or a muted, inert "Failed to check for updates" when the check dies. |
| `scripts/UpdateChecker.cs` | Update notification: once at boot it GETs the GitHub releases API for the repo's latest release (`tag_name`, `User-Agent` header, 10s timeout), compares it against the installed `config/version` from `project.godot` (`System.Version` semantics, `v` prefix and prerelease suffix tolerated) and raises `UpdateAvailable` when newer, `UpToDate` with the installed version otherwise, or `CheckFailed` when anything dies (exception, transport error, non-200, bad payload) — `MainMenu` shows the matching line either way. **The release pipeline stamps `config/version` to the build's version at build time** (`release-apk.yml`), so exported builds know their true installed version — Android's `versionName` is not reachable from Godot C#, and a hand export would compare against the repo's stale `0.0.1`. The whole flow is wrapped in try/catch so nothing escapes; failures log with an `UPDATE` prefix for headless/logcat greps. **Android: the export preset needs `permissions/internet=true` or the OS blocks every request** (Godot merges preset permissions into the generated manifest — no manual manifest edit). `LEAF_FAKE_UPDATE=<tag>` skips the network for testing (`fail` simulates a dead check). |
| `scripts/SaveData.cs` | Persistence: JSON at `user://save.json` via `FileAccess` + atomic `DirAccess.Rename`; corrupt-safe `Load` (returns fresh save; missing keys default to 0 — `gustPower` to `StartingGustPower` — so older saves keep working); `RecordClear` updates aggregates (sweeps, gusts, seconds), increments the **variant-keyed** find count and `prismaticFinds` when the bug was prismatic, + 50-entry history; `GustPower` balance persisted on every gain/spend; `BestSweeps()` for comments. |
| `scripts/BugBook.cs` | The Bug Collection Book: full-screen `CanvasLayer` (Layer 90, above the HUD) showing **one oversized page at a time** sized to the viewport (3×5 collection grid in portrait, 5×4 in landscape). Opens on the leather cover and waits; paging via **dog-eared corners** (custom `Polygon2D` fold + drop shadow + arrow: top-right forward, bottom-right back) or a horizontal swipe on the page (flick left = forward, right = back); forward turns fold the page square into the left-edge spine — the next page already sits beneath it — and a mirrored sheet unfolds on the far side through the 90° beat, while back turns lay the incoming sheet down from the spine outward (no fold first, so each direction is one motion) and the leather cover flips whole; tapping the full-rect dim (which swallows every touch so the dock stays inert) closes with a sink-and-fade. Unfound entries render their sprite through `assets/shaders/bug_mist.gdshader` (black silhouette + drifting off-black mist) labeled "??? (x0)". Content is rebuilt per page from `BugBookModel` so it always matches the save. |
| `scripts/BugBookModel.cs` | Pure (UI-free) book model: the 156 entries in stable catalog order with found state, counts and labels ("Name (xN)" / "??? (x0)"), plus the stats-page numbers (total bugs, variants/species discovered, best round, totals, prismatic finds, favorite). Autoplay asserts against the same model the UI renders. |
| `scripts/SunFlare.cs` | Yellow-sun lens flare for a prismatic discovery: additive core, streaks, rotating rays and expanding rings, self-freeing after ~1.8s. Main adds it as a **child of the celebrated bug** (relative `ZIndex` −1 + `ShowBehindParent`, so it glows exactly one rung behind the bug), letting the bug's own transform carry it from the winning tap to its seat in the win card — no cross-space position tracking, which would strand the sun in the wrong coordinate space (bug seat lives in the HUD's `CanvasLayer`, flare in the world). |
| `scripts/PrismaticGlow.cs` | Grandiose win-card dressing: a Control behind the card title drawing 14 rotating rays plus 8 looping diamond sparkles in prismatic hues; freed with the win overlay. |
| `scripts/StormDrift.cs` | One storm drift gust: a self-freeing `Node2D` raft of 6–10 decorative sprites (light/medium palette only — `Main.AirborneTextures`) that crosses the whole viewport in ~2.4s, fully offscreen on both ends. Every piece orbits a personal center riding the wind (1.4–2.2 loops per crossing, breathing lane radius, per-piece spin, downward sag) so the traces read as loose spirals; the whole motion is a function of elapsed time, so frame hiccups can't warp the path. Pure atmosphere — it touches no gameplay debris, and `Main.CancelStormDrift` ends the crossing early on win/restart/menu. |
| `scripts/Tornado.cs` | The summer tornado: a world-space prop (`ZIndex` 4, above the litter) built from the `tornado_funnel.svg` cone and a spinning `dust_ring.svg` skirt, both hung on the funnel's ground tip. `Begin(from, to)` runs the show: a ~1.5s telegraph (funnel scales up and solidifies in place, tilt-wobble and skirt spinning, litter untouched — a memory game never cheats), a ~2s crossing of the floor with a sideways weave, then a quick dissolve. Purely visual — the churn it announces lives in `Main.ShuffleRound`; `Main` polls `Telegraphing` and fires the shuffle at touchdown. `EndShow` cancels at once (win / menu / restart). |
| `scripts/WaterStream.cs` | The fall water streams: a full-floor `ColorRect` running `water.gdshader` (`ZIndex` 4, above the litter; alpha-composited, no screen read). `Begin(floorTopLeft, floorSize)` runs the show: a ~1.5s shimmer telegraph (slow brightness pulses — the wash is coming, nothing moves), a ~2s racing wash whose streak speed scales with intensity, then a quick fade. The sheet's crossing direction is random and exposed as `Direction` (+1/-1) so the shuffle can bias its targets downstream. Purely visual, like the tornado; `EndShow` cancels at once. |
| `scripts/FloorChurn.cs` | Abstract base of the season churn props (`Tornado`, `WaterStream`): `Active`/`Telegraphing`/`Begin`/`EndShow` — a telegraphed world-space show that announces itself before it touches litter, then covers the floor while `Main.ShuffleRound` moves the pieces. Purely visual, never moves a piece itself. |
| `scripts/IceBlock.cs` | The winter frozen-bug prop: a world-space ice chunk (`ZIndex` 1, beneath the litter) wrapped around the bug on blizzard rounds (`Main.OnSettleFinished` places it at the bug spot; every other round resets it). `Active` while wrapping, `ContainsPoint` for the tap hit test (forgiving 90px radius), `BlockerRadius` (55px — the chunk's visible half-extent) for the crack-eligibility and flash tests so only litter actually on the ice blocks it, `Crack()` advances through three stages — the first two swap in `ice_crack_1/2.svg` fracture overlays with a shake, the third shatters the block into a radial shard burst (10 tumbling shards, ZIndex 3) after which the node hides. `Reset()` clears shards/stage and hides the node. Input routing in `Main` (`TryIceCrackTap`): the crack is **gated on the hammer power-up** — with `_hammerArmed` set and the block clear of debris a tap cracks it, and the third crack calls `WinLevel` (the bug is picked up the moment the ice shatters); a tap on a still-covered block falls through to sweeping but first pulses the offending pieces warm (`Main.FlashIceBlockers` → `Debris.FlashBlocker`), and a tap on cleared ice without the hammer flares the chunk red (`PulseLocked`, a Modulate-only pulse disjoint from the shake's Position/Rotation wobble), so every refusal reads as a reason. |
| `scripts/StormOverlay.cs` | Storm weather: a `CanvasLayer` (Layer 2, one rung above the seasonal grade) holding a full-rect, input-transparent `ColorRect` running `assets/shaders/storm.gdshader`. `FadeIn(snow)`/`FadeOut()` tween the shader's intensity uniform (0↔1); the layer hides itself at zero intensity so non-storm rounds cost nothing. `snow` switches the storm to a blizzard (`IsSnow`): flakes instead of rain, no lightning, heavier pale fog — winter storm rounds resolve `_blizzardRound` in `Main.StartLevel`; there the flood drops snow piles while per-spot backfill restores ordinary winter litter, and both drop paths keep out of the ice rescue zone (`BlizzardRescueClearance` = `IceBlock.BlockerRadius` + widest piece extent + margin — wide enough that no weather piece's pixels can reach the ice's visible edge, so the dig stays clear once the player works it). |
| `scripts/SeasonGrade.cs` | Seasonal vibe grade: a `CanvasLayer` (Layer 1, directly above the world) holding a full-rect, input-transparent `ColorRect` running `assets/shaders/season.gdshader` — the game's only screen-reading node (one back-buffer copy per frame; every other shader stays alpha-composited). `ShowSeason(season)` applies the season's grade record (tint / saturation / brightness per `Grades[]`: Spring fresh, Summer warm golden, Fall amber, Winter cold pale) and fades the `intensity` uniform in over ~1.4s; `HideGrade()` fades out (menu returns); `Current`/`Intensity` expose state to the autoplay probe. A `ScreenReadGrade` const flips to a plain alpha-composite tint veil if a device playtest shows the screen-read cost. |
| `assets/shaders/storm.gdshader` | Full-screen weather shader: cold dark veil (~0.42 alpha) + vignette, three depth layers of *individual* rain drops (per-drop length/brightness/x-offset/speed — no uniform curtain, no global sway) falling downward and leaning downwind, rolling cloud shadows, drifting mist and fog wisps that flare in and dissipate, and a ~7s lightning double-flash; alpha-composited over the scene (no screen texture — cheaper on mobile, works headless), driven by one 0–1 `intensity` uniform. |
| `scripts/StormWarn.cs` | The "Storm Round" warning sign: a `CanvasLayer` (Layer 5) shown during the end-of-round wind of the round before a storm round (`Main.NextRoundIsStorm`); when the warned-for storm round starts the sign lingers two seconds over the round's opening (`Main.StartLevel` → `LingerThenFade`) and dissolves out over the next four seconds, while menu returns hide it at once. The label renders into a `SubViewport` whose texture feeds `assets/shaders/warn_sparks.gdshader` on a full-rect ColorRect — the shader knows where every glyph sits and repaints the sign as neon rim + lightning bolts + sparks set into a roiling storm cloud (procedural silhouette + fbm churn, no card behind); the viewport updates only while the sign is visible; the label font is shrunk by measured width until it fits the viewport; fades via root `Modulate` — the shader multiplies the incoming canvas-item modulate into its `COLOR`, so the tween reaches the pixels (drop that multiply and every fade becomes a hard cut). |
| `scripts/SeasonBanner.cs` | Season-intro banner: a `CanvasLayer` (Layer 7, one rung above the prismatic sign) showing a soft cream card (the win panel's style) near the top of the screen announcing a season change (`ShowSeason` — per-season accent + flavor line like "Fall — The rains are coming") or the year-loop bonus (`ShowLoopBonus` — "Year 2 begins — +2 Sweep Power · +1 Gust Coin" in gold). Plain labels with a root-`Modulate` fade (0.6s in, 2.2s hold, 1.2s out, self-hides — no SubViewport/shader; the neon signs own the flashy canvas), `ShowBanner(title, subtitle, accent)` is the raw entry the autoplay probe exercises; `HideBanner` kills the tween and hides at once (menu returns). |
| `scripts/PrismaticSign.cs` | The "Prismatic" banner — the storm sign's mirror image: a `CanvasLayer` (Layer 6, one rung above the storm sign so both can show when a prismatic round precedes a storm round) shown at the end of a prismatic round (`WinLevel` → `ShowSign`), anchored on a solo perch high above the centered win card; when the storm sign shares the end-round (`ShowSign(belowStormSign: _warn.Visible)`) it yields that perch and slots in **just below the storm sign's cloud** (`StormWarn.BoxBottomFraction` + gap) so neither sign overlays the other nor the "Bug found!" modal. The next `StartLevel` holds it two seconds over the round's opening (`LingerThenFade`) and dissolves it over the next four, menu returns hide it at once. Same `SubViewport` glyph-mask + full-rect ColorRect trick as `StormWarn`, feeding `assets/shaders/prismatic_sign.gdshader` (rainbow hue crawl through the lettering, specular shine bands, star glints, pastel aura; multiplies the incoming modulate into `COLOR` so the fade reaches the pixels). |
| `assets/shaders/prismatic.gdshader` | Bug-sprite overlay shader: hue-crawling rainbow wash (time + diagonal UV drift), twinkling sparkle glints on a jittered grid, and the gold outline (shared logic with `gold_outline.gdshader`) so the celebrate intensity tween still works. |
| `assets/shaders/prismatic_sign.gdshader` | "Prismatic" banner shader: reads the label's `SubViewport` render as a glyph mask (like `warn_sparks.gdshader`) and repaints the lettering as living iridescence — rainbow hue crawling through the glyphs, two bright specular bands sweeping through them, star glints clustered near the lettering, a slow-shifting pastel aura behind it. Multiplies the incoming canvas-item modulate into `COLOR` so the banner's fade tweens reach the pixels. |
| `assets/shaders/prismatic_celebration.gdshader` | Celebration tint for the end-of-round wind: one shared `ShaderMaterial` (Main-owned, picked up by every piece via `Debris.CelebrationMaterial`) whose `gold_mix` uniform Main tweens 0→1 in 0.45s on a prismatic find and 1→0 over 4s on the next `StartLevel` (the storm label's dissolve pacing; menu resets it at once). Recolors `COLOR.rgb` in place — fragment-entry `COLOR` already carries texture × modulate, so resampling `TEXTURE` would square it — mapping shaded leaf tones to gold and the brightest tips to white, luminance-mixed; at `gold_mix = 0` the shader leaves `COLOR` untouched, an exact passthrough of the default sprite pipeline. |

## Data flow

```
touch events → Main._UnhandledInput ─┬→ Sweeper (flings debris) → onSweepCompleted → LevelStats.CountSweep
                                     ├→ GustCoin.ContainsPoint + no debris overlapping → CollectCoin → +1 GustPower (persist) → GustCoin.Collect spiral
                                     ├→ Hammer.ContainsPoint + no debris overlapping → CollectHammer → clockwise spiral to the top-middle slot → floats there (arms the ice crack)
                                     ├→ IceBlock.ContainsPoint → TryIceCrackTap → hammer armed + clear: Crack + shockwave dispersal (2× burst radius, no backfill) (3rd shatters → WinLevel) / not armed: PulseLocked (red cue)
                                     ├→ Bug.ContainsPoint + no debris overlapping (BugIsCovered) → WinLevel
                                     ├→ two dead taps inside the double-tap window → Sweeper.Burst (radial fling, same 12-piece cap → onSweepCompleted)
                                     └→ covered coin/bug, or elsewhere → Sweeper.Begin
HUD wind button → Main.OnWindPressed → −1 GustPower (persist) + LevelStats.CountGust
WinLevel → LevelStats.Stop → SaveData.RecordClear → Bug.Celebrate → CelebrationFinished → Hud.ShowWin(comment, stats)
         └→ StartEndRoundWind → every unswept piece rides a clockwise gyre (Debris.StartEndRoundWind) until the round is torn down
         └→ next round is a storm round → StormWarn.ShowWarning (electrical "Storm Round" sign; it lingers 2s into the storm round's opening, then fades out over 4s)
         └→ prismatic find → PrismaticSign.ShowSign (shiny "Prismatic" banner; the next StartLevel holds it 2s over the opening, then fades it out over 4s; menu returns hide it)
StartLevel → SpawnDebris (SettleIn tumble-drop, diagonal stagger) → [touches locked] → OnSettleFinished → bug + 3 gust coins hidden at random spots under the settled debris, round clock starts
Storm round (live + settled) → each recorded cleared spot fires on its own 4–6s timer (Main.TickStormDrops) → one fresh piece tumbles onto that exact ground (SettleIn tumble, spot consumed, pool capped at 400) → fresh unswept debris re-covers the bug/coins via the normal overlap rules
Storm flood (live + settled) → every 4–6s (Main.TickClusterDrops) a cluster of 6–12 brand-new pieces tumbles onto random floor spots — 20–34 on blizzard rounds (WinterFloodMin/Max) — (same SpawnStormDebris path) → the litter grows past the round's starting count → once the live count reaches 3× the start (StormFloodCapMultiplier, final cluster truncated to fit) the flood abates for the round; spot restoration continues regardless
StartLevel → SpawnDebris (SettleIn tumble-drop, diagonal stagger) → [touches locked] → OnSettleFinished → bug + gust coins (`GustCoinsForLevel`: 1 normal / 3 storm) hidden at random spots under the settled debris, round clock starts
Dock restart → OnRestartConfirmed → StartLevel (same settle reshuffle: fresh curtain, new hiding spots)
Main._Process (round live + settled) → every 2–4s (storm: every ~0.7–1.3s) → TriggerAmbientRustle → epicenter + the closest 4–7 at-rest pieces shiver along a shared draft (Debris.Rustle, sprite-only wiggle)
Storm round (live + settled) → every 10–20s → TriggerSpiralRustle → the at-rest litter within a swirl radius (1/10 of the playable floor's smaller dimension) shivers along the clockwise tangent, delayed by clockwise angle → a spinning wave of shivers, purely cosmetic
Storm round (live + settled) → every 10–20s (independent timer) → SpawnStormDrift → a StormDrift raft of decorative sprites spirals across the screen offscreen-left → offscreen-right in ~2.4s, freeing itself at the far edge (no gameplay debris touched)
App boot / Menu → SpawnMenuDebris (scatter over the full screen, no drop-in) → StartEndRoundWind(MenuWindSpeedScale) → litter slowly circles behind the menu card
```

`ToWorld()` maps screen → world through `GetCanvasTransform().AffineInverse()`
so UI-anchored touches match world-space debris under stretch/expand.

## Rendering notes

- Base viewport **1080×2340**, stretch mode `canvas_items`, aspect `expand` —
  taller/shorter phones simply show more/less ground; the ground sprite is
  rescaled on startup, every round **and on every viewport resize**
  (`Main.OnViewportResized`), which also stretches a live round's unswept
  debris + bug positions onto the new rect so no bare floor shows mid-level.
- Portrait orientation, touch emulation from mouse for desktop testing.
- Textures are SVGs rasterized by Godot at import; the source is regenerated
  by `tools/gen_art.mjs`.

  one `AUTOPLAY ... True` line per assertion (menu, catalog 39/156, restart,
  rustle, spiral gust, drift raft, uncover, prismatic spawn, burst, coins,
  storm drops landing on
  recorded cleared spots with the pool shrinking, flood clusters growing the

  + the prismatic banner shown/lingering/fading and the litter's
  gold/white celebration tint releasing after a save round-trip).
  The autoplay round forces the prismatic roll so the rare path is
  exercised every run, and forces the storm weather too; the cosmetic
  storm event timers (rustle pacing, spiral gusts, drift rafts) are
  suppressed and triggered by hand for determinism.

- `LEAF_AUTOPLAY=1 godot --headless` → verifies the save round-trip and exits
  0/1 (grep for `AUTOPLAY` first — the exit code alone is not trustworthy).
  Used by CI-style smoke checks.

  be tested by hand (autoplay forces it internally every run).

  every 10th level; autoplay forces it internally every run).
- `godot --headless --quit-after N` → boot smoke test.
